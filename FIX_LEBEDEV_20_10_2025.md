# КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ - Порог активностей для маркеров

## Дата: 20.10.2025

## Проблема

**Сотрудник Лебедев Андрей Валериевич** неправильно показывался как "Свободная вахта", хотя он **РЕАЛЬНО НА ОБЪЕКТЕ**!

### Данные Лебедева:
```
17.10 - 📋 Инструктаж      [МАРКЕР НАЧАЛА]
19.10 - ⏸️ Простой         [РАБОТА #1]
19.10 - ⏸️ Простой         [РАБОТА #2]
```

### Что было:
- **Старая логика**: требовала **>2 работ** (минимум 3) после маркера
- **Результат**: 2 работы < 3 → НЕ на объекте → показан как "Свободная вахта" ❌ **НЕПРАВИЛЬНО!**

### Что должно быть:
- **Новая логика**: требует **>0 работ** (минимум 1) после маркера
- **Результат**: 2 работы > 0 → НА ОБЪЕКТЕ ✅ **ПРАВИЛЬНО!**

## Обоснование изменения

### Старая логика была СЛИШКОМ СТРОГОЙ:

Если сотрудник:
1. Прошел **Инструктаж** (официальное начало работы)
2. Выполнил **ХОТЯ БЫ ОДНУ** рабочую активность

То он **УЖЕ НАХОДИТСЯ НА ОБЪЕКТЕ**!

Не имеет смысла требовать 3+ активности. Даже 1 работа после Инструктажа означает, что сотрудник приступил к обязанностям.

### Примеры когда старая логика ломалась:

**Пример 1: Простой на объекте**
```
17.10 - Инструктаж
18.10 - Простой (плохая погода)
19.10 - Простой (нет материалов)

Старая логика: НЕ на объекте (всего 2 активности)
Реальность: НА ОБЪЕКТЕ (сотрудник ждет на месте!)
```

**Пример 2: Короткая командировка**
```
18.10 - Дорога
19.10 - Монтаж оборудования
20.10 - (сегодня, еще работает)

Старая логика: НЕ на объекте (всего 1 активность)
Реальность: НА ОБЪЕКТЕ (выполняет работу!)
```

## Изменения в коде

### Файл: `PersonnelService.php`

#### 1. Метод `findSessionWithMarker()`:

**БЫЛО:**
```php
// Requires >2 (minimum 3) work activities after marker
if ($workActivitiesAfter > 2) {
    return $markerDate;
}
```

**СТАЛО:**
```php
// Requires >0 (minimum 1) work activities after marker
// If employee passed briefing/road and did ANY work - they are on-site!
if ($workActivitiesAfter > 0) {
    return $markerDate;
}
```

#### 2. Метод `findSessionClosureWithMarker()`:

**БЫЛО:**
```php
// Requires >2 (minimum 3) work activities before marker
if ($workActivitiesBefore > 2) {
    return $closingMarkerDate;
}
```

**СТАЛО:**
```php
// Requires >0 (minimum 1) work activities before marker
// If employee did ANY work before going home - valid session closure
if ($workActivitiesBefore > 0) {
    return $closingMarkerDate;
}
```

## Обновленная логика

### Сценарий 1: Сессия с маркером

```
ЕСЛИ есть маркер начала (Дорога/Инструктаж):
    
    ЕСЛИ после маркера есть >0 работ (минимум 1):
        
        ЕСЛИ последняя запись = Дорога/Аванс:
            → Сессия ЗАКРЫТА
        
        ИНАЧЕ:
            → Сессия ОТКРЫТА
            → НА ОБЪЕКТЕ с даты маркера
```

### Сценарий 2: Закрытие сессии

```
ЕСЛИ есть маркер закрытия (Дорога/Аванс):
    
    ЕСЛИ перед маркером было >0 работ (минимум 1):
        → Сессия корректно закрыта
        → СВОБОДНАЯ ВАХТА с даты маркера
```

### Сценарий 3: Без маркеров

```
ЕСЛИ нет маркеров:
    
    ЕСЛИ есть >4 непрерывных работ (минимум 5):
        
        ЕСЛИ последняя работа ≤3 дней назад:
            → НА ОБЪЕКТЕ
```

**Примечание**: Для сессий БЕЗ маркеров порог остается **>4** (минимум 5), так как это единственный способ отличить реальную работу от случайных активностей.

## Гарантия от повторения

Эта ошибка **НИКОГДА НЕ ПОВТОРИТСЯ** потому что:

1. ✅ Любой сотрудник с маркером + хотя бы 1 работа → НА ОБЪЕКТЕ
2. ✅ Любой сотрудник с работой + маркер закрытия → СВОБОДНАЯ ВАХТА
3. ✅ Логика максимально мягкая для маркеров (>0 = минимум 1)
4. ✅ Логика строгая для немаркированных сессий (>4 = минимум 5)
