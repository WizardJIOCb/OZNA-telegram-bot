# ИСПРАВЛЕНИЕ: Личный чат не должен отправлять в группу

## Проблема

Когда пользователь настраивал проект на контроле и выбирал "Личный чат", отчеты отправлялись **И в группу, И в личный чат**, что создавало дублирование.

**Найденный проблемный случай:**
- **Пользователь**: Калимуллин Родион Данирович (ID: 230379668)
- **ФН**: Мобильная бригада
- **Проект**: ОИ834
- **Настройки**:
  - `group_id`: `-1002722176147` (группа Мобильной бригады)
  - `chat_id`: `personal` (личный чат)

**Результат ДО исправления:**
При отправке отчета по проекту ОИ834, он попадал в **3 места**:
1. ✅ Группа и тема согласно ФН отправителя
2. ❌ Группа Мобильной бригады (основная лента) - через "Проекты на контроле"
3. ❌ Личный чат Калимуллина - через "Проекты на контроле"

## Решение

Изменена логика в [`TabelEntry.php`](c:\ozna_bot\CustomCommands\Services\TabelEntry.php):

### 1. Исправлена логика отправки (строки 1030-1064)

**БЫЛО (неправильно):**
```php
// Сначала отправляем в группу (если есть group_id)
if (!empty($projectSettings['group_id'])) {
    // отправка в группу
}

// ЗАТЕМ также отправляем в личный чат (если chat_id = 'personal')
if ($projectSettings['chat_id'] === 'personal') {
    // отправка в личный чат
}
```

**СТАЛО (правильно):**
```php
// Если выбран личный чат - отправляем ТОЛЬКО туда (НЕ в группу!)
if ($projectSettings['chat_id'] === 'personal') {
    // отправка ТОЛЬКО в личный чат
} 
// Иначе отправляем в группу
elseif (!empty($projectSettings['group_id'])) {
    // отправка в группу
}
```

### 2. Обновлена функция проверки дублирования (строки 1100-1127)

Добавлена проверка в начале функции `isDuplicateDestination()`:

```php
// Если chat_id = 'personal', то отчет идет ТОЛЬКО в личный чат, не в группу
// Поэтому это НЕ дублирование
$projectThreadId = $projectSettings['chat_id'] ?? null;
if ($projectThreadId === 'personal') {
    return false;
}
```

## Результат ПОСЛЕ исправления

Теперь при настройке `chat_id = 'personal'`:

### ✅ Правильное поведение:
1. ✅ Обычная отправка → согласно ФН отправителя (в его группу и тему)
2. ✅ Копия через "Проекты на контроле" → **ТОЛЬКО в личный чат** супервайзера
3. ❌ ~~В группу Мобильной бригады~~ → **НЕ отправляется!**

**Group ID теперь ИГНОРИРУЕТСЯ**, если выбран `chat_id = 'personal'`

## Что изменилось для пользователей

### Вариант 1: Chat ID = "personal"
- **Было**: Отчет попадал в группу (указанную в Group ID) + в личный чат
- **Стало**: Отчет попадает **ТОЛЬКО в личный чат** (Group ID игнорируется)

### Вариант 2: Chat ID = номер темы (например, "2", "338")
- **Было и осталось**: Отчет попадает в группу (Group ID) в указанную тему (Chat ID)
- Без изменений

### Вариант 3: Chat ID пустой
- **Было и осталось**: Отчет попадает в группу (Group ID) в основную ленту
- Без изменений

## Рекомендации для пользователей

Если у проекта на контроле указаны **оба параметра**:
- `group_id`: `-1002722176147`
- `chat_id`: `personal`

То после исправления `group_id` будет **игнорироваться**.

### Если хотите получать отчеты:
1. **Только в личный чат** → Оставьте `chat_id = 'personal'` (Group ID будет игнорирован)
2. **В группу в конкретную тему** → Измените `chat_id` на номер темы (например, "87", "338")
3. **В группу в основную ленту** → Удалите или очистите `chat_id`, оставьте только `group_id`
