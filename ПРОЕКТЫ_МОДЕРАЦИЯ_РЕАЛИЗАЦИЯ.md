### Шаг 1: Создать таблицу в БД

Выполните SQL скрипт в базе данных:

```bash
mysql -u WizardJIOCb -p tg_bot < database/migrations/create_project_moderation_table.sql
```

Или вручную через phpMyAdmin / MySQL Workbench:
- Откройте файл `database/migrations/create_project_moderation_table.sql`
- Скопируйте и выполните SQL запрос

### Шаг 2: Миграция существующих проектов (опционально)

Если хотите перенести существующие проекты из `data/projects.json` в таблицу БД:

```sql
-- Пример: добавить существующие проекты как уже одобренные
INSERT INTO project_moderation (project_code, original_name, current_name, status, added_by, added_at, moderated_by, moderated_at, is_active)
VALUES 
  ('ОИ834', 'ОИ834', 'ОИ834', 'active', 0, NOW(), 0, NOW(), 1),
  ('ОИ651', 'ОИ651', 'ОИ651', 'active', 0, NOW(), 0, NOW(), 1),
  ('ОИ696', 'ОИ696', 'ОИ696', 'active', 0, NOW(), 0, NOW(), 1)
  -- ... добавить все проекты из data/projects.json
ON DUPLICATE KEY UPDATE status = status;
```

### Шаг 3: Проверка webhook

Убедитесь, что webhook работает:

```bash
curl https://ваш-домен/hook.php
```

### Шаг 4: Тестирование

## 🎯 Основные возможности

### Для пользователей

1. **Автономное добавление проектов**
   - Проект сразу доступен для работы
   - Не нужно ждать администратора

2. **Уведомления о модерации**
   - Проект одобрен
   - Проект переименован (с информацией об обновлении записей)
   - Проект отклонён (с причиной)

### Для администраторов

1. **Централизованная модерация**
   - Все проекты в одном месте
   - Счётчик pending-проектов в админ-панели

2. **Мощные инструменты**
   - Одобрение проекта (1 клик)
   - Переименование с автообновлением ВСЕХ записей табеля
   - Отклонение с указанием причины

3. **Уведомления**
   - Получают уведомление о каждом новом проекте
   - Информация о пользователе, добавившем проект

## 🔧 Технические детали

### Валидация названий проектов

Используются те же правила, что в `AdminService::addProject()`:
- `trim(strtoupper($projectCode))` - приведение к верхнему регистру
- От 3 до 50 символов
- Проверка на дубликаты (case-insensitive)

### Статусы проектов

- `pending` - Ожидает модерации
- `active` - Одобрен администратором
- `renamed` - Переименован администратором
- `rejected` - Отклонён администратором

### Безопасность

- Добавление проектов: только уровень ≥ 1 (не гости)
- Модерация проектов: только уровень ≥ 2 (Supervisor+)
- Все изменения логируются в error_log

### Переименование проектов

При переименовании проекта:
1. Обновляется запись в `project_moderation`
2. **Автоматически обновляются ВСЕ записи в таблице `tabel`**
3. Изменения выполняются в транзакции (rollback при ошибке)
4. Пользователь получает уведомление

Пример:
```
Было: бкнс-150 (10 записей табеля)
Стало: БКНС-150
Результат: Все 10 записей автоматически обновлены!
```

## 📊 Структура callback'ов

### Пользовательская часть
- `proj_mod_add_new` - Начать добавление нового проекта

### Административная часть
- `category_Админка_МодерацияПроектов` - Список проектов на модерации
- `proj_mod_view_{ID}` - Просмотр деталей проекта
- `proj_mod_approve_{ID}` - Одобрить проект
- `proj_mod_rename_start_{ID}` - Начать переименование
- `proj_mod_reject_start_{ID}` - Начать отклонение

### Conversation states
- `project_mod_action` = `'add_new'` - Пользователь вводит название нового проекта
- `project_mod_action` = `'rename'` - Админ вводит новое название для переименования
- `project_mod_action` = `'reject'` - Админ вводит причину отклонения

## 🐛 Возможные проблемы и решения

### Проблема: Таблица не создаётся

**Решение**: Проверьте права доступа к БД:
```sql
SHOW GRANTS FOR 'WizardJIOCb'@'%';
```

Должно быть: `GRANT ALL PRIVILEGES ON tg_bot.*`

### Проблема: Callback proj_mod_ не обрабатывается

**Решение**: Проверьте лог:
```bash
tail -f /path/to/error.log | grep "proj_mod"
```

Убедитесь, что в `CallbackqueryCommand.php` разрешены `proj_mod_` callbacks.

### Проблема: DatabaseService не находит методы модерации

**Решение**: Проверьте, что методы добавлены в конец `DatabaseService.php` перед закрывающей скобкой класса.

### Проблема: Счётчик проектов не отображается

**Решение**: Проверьте, что `AdminHandler.php` получает `databaseService` через:
```php
$databaseService = $this->adminService->getDatabaseService();
```

## 📈 Метрики

После развёртывания вы сможете отслеживать:
- Количество проектов на модерации
- Среднее время модерации
- % одобренных/переименованных/отклонённых проектов
- Самых активных пользователей по добавлению проектов

Запросы для аналитики:

```sql
-- Статистика модерации
SELECT 
  status, 
  COUNT(*) as count,
  ROUND(COUNT(*) * 100.0 / (SELECT COUNT(*) FROM project_moderation), 2) as percentage
FROM project_moderation
GROUP BY status;

-- Топ пользователей по добавлению проектов
SELECT 
  added_by,
  COUNT(*) as projects_added
FROM project_moderation
GROUP BY added_by
ORDER BY projects_added DESC
LIMIT 10;

-- Среднее время модерации (в часах)
SELECT 
  AVG(TIMESTAMPDIFF(HOUR, added_at, moderated_at)) as avg_hours
FROM project_moderation
WHERE moderated_at IS NOT NULL;
```
