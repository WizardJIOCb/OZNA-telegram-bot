# 🎯 Краткая Инструкция: Предотвращение Дублирования Отчетов

## ✅ Что Реализовано

Система теперь **автоматически блокирует** повторную отправку одинаковых отчетов в течение **24 часов**.

## 🔧 Технические Изменения

### 1. DatabaseService.php
Добавлен метод для проверки дубликатов:
```php
public function checkDuplicateActivityReport(
    int $userId, 
    string $activityType, 
    string $projectCode = ''
): ?array
```

### 2. TabelEntry.php
Метод `addEntry()` теперь:
1. Проверяет наличие дубликата **перед** сохранением
2. Блокирует сохранение если найден дубликат
3. Отправляет пользователю понятное сообщение

```
             ↓

             ↓
```

```
администратору."
```

## 📋 Что Считается Дубликатом

### ❌ ДУБЛИКАТ (блокируется)
- Один пользователь
- Одна активность (например, "Работы по графику")
- Один проект (например, ОИ834)
- В течение 24 часов

### ✅ НЕ ДУБЛИКАТ (разрешается)
- Разные проекты (ОИ834 ≠ ОИ651)
- Разные активности (Работы по графику ≠ Формирование ИД)
- Прошло более 24 часов

## 🧪 Как Протестировать

### Вручную в Telegram
1. Отправь отчет обычным способом
2. Сразу же попытайся отправить тот же отчет
3. Должно появиться сообщение о блокировке
4. Проверь, что в базе НЕ появился дубликат

### Проверка Логов
```bash
# Найти заблокированные дубликаты
grep "DUPLICATE DETECTED" /var/log/bot.log

# Посчитать количество
grep "DUPLICATE DETECTED" /var/log/bot.log | wc -l
```

## 📊 Мониторинг

### Команды для Мониторинга

```bash
# Сколько дубликатов заблокировано сегодня
grep "DUPLICATE DETECTED" /var/log/bot.log | grep "$(date +%Y-%m-%d)" | wc -l

# Кто чаще всего пытается отправить дубликаты
grep "DUPLICATE DETECTED" /var/log/bot.log | grep -oP 'User \d+' | sort | uniq -c | sort -rn | head -10

# Какие активности чаще всего дублируются
grep "DUPLICATE DETECTED" /var/log/bot.log | grep -oP "activity '.+?'" | sort | uniq -c | sort -rn | head -10
```

## 🚨 Частые Вопросы

### Q: Пользователь отправил неправильный отчет, как исправить?

**A:** Удалить запись из базы данных:

```sql
-- Найти запись
SELECT * FROM ozna_tabel 
WHERE user_id = 12345 
AND dt > DATE_SUB(NOW(), INTERVAL 24 HOUR)
ORDER BY dt DESC;

-- Удалить неправильную запись
DELETE FROM ozna_tabel WHERE id = [ID записи];
```

После удаления пользователь сможет отправить новый отчет.

### Q: Можно ли изменить период блокировки?

**A:** Да, измени `INTERVAL 24 HOUR` в методе `checkDuplicateActivityReport`:

```php
// Было: 24 часа
AND dt >= DATE_SUB(NOW(), INTERVAL 24 HOUR)

// Например, на 4 часа
AND dt >= DATE_SUB(NOW(), INTERVAL 4 HOUR)
```

### Q: Как отключить проверку для определенной активности?

**A:** Добавь исключение в `TabelEntry::addEntry()`:

```php
// Исключения для активностей, которые можно отправлять многократно
$excludedActivities = ['Прочее_ЭлектрОб', 'Прочее_Автом'];

if (in_array($activityType, $excludedActivities)) {
    error_log("⏭️ Skipping duplicate check for excluded activity: {$activityType}");
    // Пропустить проверку дубликатов
} else {
    // Обычная проверка
    $existingReport = $this->databaseService->checkDuplicateActivityReport(...);
}
```
