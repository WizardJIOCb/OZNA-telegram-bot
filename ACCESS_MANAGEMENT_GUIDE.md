# Руководство по управлению уровнями доступа

## Обзор системы уровней доступа

Система имеет 5 уровней доступа:
1. **Гость (0)** - Только доступ к профилю
2. **Пользователь (1)** - Доступ ко всем функциям, кроме админки и супервайзера
3. **Супервайзер (2)** - Доступ к отчетам и расширенным функциям
4. **Администратор (3)** - Доступ к админке и возможность подтверждать заявки
5. **Суперадминистратор (4)** - Полный доступ, назначение админов и супервайзеров

## Управление уровнями доступа через базу данных

### Проверка текущего уровня доступа пользователя

```sql
SELECT user_id, data FROM ozna_data WHERE user_id = [USER_ID];
```

В поле `data` будет JSON, содержащий уровень доступа:
```json
{
  "access_level": 2,
  "fio": "Иванов Иван Иванович",
  "functional_direction": "Мобильная бригада"
}
```

### Обновление уровня доступа пользователя

```sql
UPDATE ozna_data 
SET data = JSON_REPLACE(data, '$.access_level', [NEW_LEVEL]) 
WHERE user_id = [USER_ID];
```

Примеры:
- Назначить супервайзером (уровень 2):
  ```sql
  UPDATE ozna_data 
  SET data = JSON_REPLACE(data, '$.access_level', 2) 
  WHERE user_id = 123456789;
  ```

- Назначить администратором (уровень 3):
  ```sql
  UPDATE ozna_data 
  SET data = JSON_REPLACE(data, '$.access_level', 3) 
  WHERE user_id = 123456789;
  ```

- Сбросить до гостя (уровень 0):
  ```sql
  UPDATE ozna_data 
  SET data = JSON_REPLACE(data, '$.access_level', 0) 
  WHERE user_id = 123456789;
  ```

## Работа с заявками на доступ

### Просмотр заявок

Заявки хранятся в файле `data/access_requests.json`:
```json
[
  {
    "user_id": 123456789,
    "user_name": "Тестовый пользователь",
    "user_telegram_name": "Test User",
    "user_fio": "Иванов Иван Иванович",
    "chat_id": "987654321",
    "timestamp": 1725120000
  }
]
```

### Одобрение заявки

1. Обновите уровень доступа пользователя до уровня Администратор (3) или Супервайзер (2)
2. Удалите запись из файла `access_requests.json`

### Отклонение заявки

1. Просто удалите запись из файла `access_requests.json`

## Получение первых администраторов

### Шаг 1: Определите пользователей для назначения администраторами

Выберите пользователей, которые будут первыми администраторами. Вам понадобятся:
- User ID
- Chat ID (для отправки уведомлений)

### Шаг 2: Обновите уровень доступа

Для каждого выбранного пользователя выполните SQL-запрос:
```sql
UPDATE ozna_data 
SET data = JSON_REPLACE(data, '$.access_level', 3) 
WHERE user_id = [USER_ID];
```

### Шаг 3: Уведомите пользователей

Отправьте сообщение каждому новому администратору:
```
✅ Доступ предоставлен

Вам предоставлен доступ к административным функциям бота.
Теперь вы можете использовать все функции админки.
```

## Сброс всех пользователей до уровня Гость

### ВНИМАНИЕ: Эта операция необратима!

1. Создайте резервную копию таблицы `ozna_data` перед выполнением

2. Выполните SQL-запрос для сброса всех пользователей (кроме суперадминов):
```sql
UPDATE ozna_data 
SET data = JSON_REPLACE(data, '$.access_level', 0) 
WHERE JSON_EXTRACT(data, '$.access_level') > 0 
AND user_id NOT IN (230379668, 5261465966, 1090118386, 444234398);
```

3. Отправьте уведомление всем пользователям:
```
ℹ️ Обновление доступа

В боте внедрена новая система уровней доступа.
Ваш уровень доступа был сброшен до уровня Гость.

Для получения доступа к функциям бота необходимо подать заявку через меню Профиль → Уровень доступа.
```

## Тестирование системы

### Проверка текущих уровней доступа

1. Выберите нескольких пользователей для тестирования
2. Проверьте их текущие уровни доступа через базу данных
3. Убедитесь, что суперадмины имеют уровень 4

### Тестирование заявок на доступ

1. Создайте тестовую заявку в файле `access_requests.json`
2. Используйте админ-панель для одобрения заявки
3. Проверьте, что уровень доступа пользователя обновился
4. Убедитесь, что заявка удалена из файла

### Тестирование сброса уровней

1. Назначьте тестовому пользователю уровень администратора
2. Выполните сброс до уровня гостя
3. Проверьте, что уровень действительно сброшен

### Тестирование функций супервайзера

1. Назначьте тестовому пользователю уровень супервайзера
2. Проверьте доступ к функциям супервайзера через меню
3. Убедитесь, что отображаются соответствующие кнопки в главном меню

## Часто возникающие проблемы

### Заявка одобрена, но доступ не предоставлен

1. Проверьте, что функция `approveAccessRequest` в `AdminService.php` правильно обновляет уровень доступа
2. Убедитесь, что `updateUserAccessLevel` в `DatabaseService.php` корректно сохраняет данные

### Пользователь не может получить доступ к админке

1. Проверьте уровень доступа пользователя
2. Убедитесь, что проверка уровня доступа в `AdminHandler.php` работает правильно
3. Проверьте, что пользователь не заблокирован

### Пользователь не видит кнопку супервайзера в главном меню

1. Проверьте уровень доступа пользователя
2. Убедитесь, что метод `createMainMenuKeyboard` в `MessageService.php` правильно проверяет уровень доступа
3. Проверьте, что изменения в коде были применены
