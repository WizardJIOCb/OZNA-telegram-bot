# 📦 Инструкция для администратора сервера

## Что нужно сделать:

Обновить 3 файла на сервере и перезапустить PHP-FPM.

---

## 📁 Файлы для обновления:

1. **CustomCommands/Handlers/ProjectHandler.php**
2. **CustomCommands/GenericmessageCommand.php**
3. **CustomCommands/Services/DatabaseService.php**

*(Файлы находятся в той же папке, что и эта инструкция)*

---

## 🔧 Пошаговая инструкция:

### Шаг 1: Загрузить файлы на сервер

Замените эти 3 файла в директории проекта `/var/www/api.ladyzenko.pro/tg/ozna/`:

```
/var/www/api.ladyzenko.pro/tg/ozna/CustomCommands/Handlers/ProjectHandler.php
/var/www/api.ladyzenko.pro/tg/ozna/CustomCommands/GenericmessageCommand.php
/var/www/api.ladyzenko.pro/tg/ozna/CustomCommands/Services/DatabaseService.php
```

### Шаг 2: Проверить права доступа

```bash
cd /var/www/api.ladyzenko.pro/tg/ozna/
chmod 644 CustomCommands/Handlers/ProjectHandler.php
chmod 644 CustomCommands/GenericmessageCommand.php
chmod 644 CustomCommands/Services/DatabaseService.php
chown www-data:www-data CustomCommands/Handlers/ProjectHandler.php
chown www-data:www-data CustomCommands/GenericmessageCommand.php
chown www-data:www-data CustomCommands/Services/DatabaseService.php
```

*(Замените `www-data` на пользователя веб-сервера, если он другой)*

### Шаг 3: Перезапустить PHP-FPM

```bash
# Узнать версию PHP
php -v

# Перезапустить соответствующую версию:
sudo systemctl restart php8.3-fpm
# или
sudo systemctl restart php8.2-fpm
# или
sudo systemctl restart php-fpm
```

### Шаг 4: Проверить, что всё работает

1. Попросите пользователя зайти в бот
2. Нажать: **📁 Проекты** → **📋 Отчёт по проекту** → **📊 Простой отчёт**
3. Должно появиться: **"Введите дату начала отчёта в формате ДД.ММ.ГГГГ"**

---

## 🔍 Диагностика (если не работает):

### Проверка 1: Файлы загружены?

```bash
cd /var/www/api.ladyzenko.pro/tg/ozna/
ls -la CustomCommands/Handlers/ProjectHandler.php
ls -la CustomCommands/GenericmessageCommand.php
ls -la CustomCommands/Services/DatabaseService.php
```

Проверить дату изменения - должна быть сегодняшняя.

### Проверка 2: Логи в реальном времени

```bash
tail -f /var/log/nginx/error.log | grep DEBUG_SIMPLE_REPORT
```

Попросить пользователя нажать кнопку "Простой отчёт".

**Должны появиться такие логи:**
```
DEBUG_SIMPLE_REPORT: handleProjectReportCallback called with: proj_report_simple
DEBUG_SIMPLE_REPORT: Matched proj_report_simple, calling showSimpleReportStartDateMenu
DEBUG_SIMPLE_REPORT: showSimpleReportStartDateMenu called for user: [ID]
DEBUG_SIMPLE_REPORT: Conversation state set, awaiting_simple_report_start_date = true
```

**Если логов нет:**
- Файлы не обновлены
- Или PHP-FPM не перезапущен

**Если есть ошибки:**
- Скопировать текст ошибки и отправить пользователю

### Проверка 3: Очистить OPcache (если используется)

```bash
# Создать файл для очистки кеша
echo '<?php opcache_reset(); echo "Cache cleared"; ?>' > /var/www/api.ladyzenko.pro/tg/ozna/clear_cache.php

# Открыть в браузере
curl https://api.ladyzenko.pro/tg/ozna/clear_cache.php

# Удалить файл после использования
rm /var/www/api.ladyzenko.pro/tg/ozna/clear_cache.php
```

Затем пользователь вводит дату, выбирает дату окончания, выбирает функциональное направление и получает файл с отчётом.
